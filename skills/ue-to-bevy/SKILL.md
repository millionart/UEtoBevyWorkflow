# UE to Bevy

Read the template [README](../../README.md) for setup and commands. Establish the requesting project's scope and its local source and target versions. Treat local source assets, APIs and actual consumers as the specification. Use the repository's native editor reader and the configured project. The project operator owns any local editor configuration and external engine changes.

1. **Inventory the slice.** Map source responsibilities to target modules, extension points and final consumers. List dependencies before proposing implementation. Record exclusions and deliberate differences. In a review, report unobserved behavior separately from confirmed differences and defer implementation until the user authorizes it.
2. **Extract a source contract.** Capture the asset and follow compiled data, linked packages, graph and state machine edges, pins, defaults, relevant code, asset selection and lifecycle. For linked graphs or instances, record the owning object, the calling pin, and evaluation phase. Re-read changed dependencies from the same source configuration. A missing reader field leaves verification open; extend the reader using the local engine API when the field is required.
3. **Translate by responsibility.** Reuse a public target feature when the input, algorithm, clock and output contract match. Place project-specific rules and node implementations in the target project. Dispatch converter rules by source class, pin schema or function signature. Use identifiers as data. Emit an actionable failure for an unsupported input before creating runtime artifacts. Read the original export without editing it, and generate target assets into separate paths. Compare the full regenerated corpus after shared rule changes.
4. **Map units and stages.** Derive coordinate basis, handedness, parent space, scale and parameter units together before converting transforms. Verify basis vectors, rotation and field recomposition. Match initialization, conditional rebuilds, events and frame updates to source ordering. Use source and target execution semantics for accumulated time, fixed steps and substeps. Start pose and IK with current-frame input and apply physics readback at its defined boundary.
5. **Prove the first violating boundary.** Reproduce a reported difference with a focused case and comparable inputs. Record why broader tests missed it. Change the first consumer or converter stage shown to violate the contract. Remove each proposed adapter, state or branch in a controlled check and keep it only if the relevant test detects the difference. Preserve observed tolerances, including underlying solver differences when the operator accepts them.
6. **Verify the real entry point.** Complete source, static and focused checks before compiling and running the affected features in the consuming project's existing scene. Graph coverage includes reachable states and dependencies, exact node and pin identities, links, default values, timing and actual pose and curve outputs. For a graph error, report the original error, node or pin, candidate asset, pose classification and scenario label. Use a progress watchdog for automated work and verify both termination and normal completion.
7. **Leave a repeatable result.** Record the minimal tests, actual outcomes and untested boundaries. Keep numerical inputs and target expectations in small fixtures. Treat engine captures, editor logs and version-specific diagnostic data as local outputs unless the project explicitly needs them retained. Keep local configuration and account information out of the shared template.

Begin with the shipped graph and rig analyses when entering a new target. Their output identifies expansion points. The stock graph compiler covers a single non-looping clip. Add target-specific rules and runtime node registration as a pair, then re-run a supported and a rejected case. For a new subsystem, add an extraction step and an independently testable converter that preserve the same source-to-consumer contract.
